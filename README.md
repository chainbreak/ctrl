# Ctrl Messenger

Исходный код Ctrl Messenger, веб-интерфейса, серверных компонентов, мобильных клиентов и TON-подсистемы.

Эта папка подготовлена как отдельная копия для публикации на GitHub. Текущая версия исходников — beta v0.1.2. Старые установщики сюда не входят: сначала пересоберите приложение из этих исходников, затем приложите новые файлы к GitHub Release `beta-v0.1.2`.

## Состав проекта

- `assets/` — интерфейсные скрипты, стили и клиентские ресурсы. Подарки сгруппированы по ID в `assets/gifts/<gift-id>/`.
- `backend/Ctrl.Api/` — ASP.NET Core API и панель сотрудников.
- `mobile/` — Android и iOS-клиенты.
- `protocol-ui/` — исходный код клиентской Signal-интеграции.
- `ton/` — FunC-контракты, Blueprint-проект, тесты и TON Connect-аутентификация.
- `windows/` — Windows desktop-клиент, сервер, проверяющие TON-компоненты и сборочные скрипты.
- `index.html`, `market.html`, `test.html` — страницы проекта и интерфейс приложения. `windows/BuildInterface.ps1` использует `test.html` как исходную страницу встроенного интерфейса.

Файлы подарков хранятся рядом в собственной папке: анимация — `animation.*`, превью — `poster.*`. Сборка Windows рекурсивно включает всё содержимое `assets/gifts/` в пакет интерфейса.

Сгенерированные зависимости и результаты сборки намеренно не включены. В частности, папки `node_modules`, `bin`, `obj`, `publish-*`, `staging` и `ton/build` должны создаваться повторно локальными командами сборки.

## Требования

- Node.js 24 или новее для TON-проектов и сборочных скриптов Windows.
- .NET SDK 8 для Windows-сервера и desktop-клиента.
- .NET SDK 10 для панели API и Android-проекта; для Android также нужны соответствующие workloads.
- Для запуска Windows desktop-клиента — Windows x64 и WebView2 Runtime.
- Для сборки iOS-клиента — macOS, Xcode и настроенная Apple Development Team.

## Проверки и сборка

Проверить и собрать TON-контракты из каталога `ton`:

```powershell
npm ci
npm test
```

Собрать Windows-сервер и desktop-клиент из `windows`:

```powershell
.\BUILD.ps1
```

Скрипт собирает интерфейс и приложения в `publish-*`. Эти результаты игнорируются Git и не должны коммититься.

Собрать панель API из корня проекта:

```powershell
dotnet build backend/Ctrl.Api/Ctrl.Api.csproj -c Release
```

Опубликовать Android ARM64-клиент:

```powershell
dotnet publish mobile/android/Ctrl.Android.csproj -c Release -r android-arm64
```

Для изменения `protocol-ui/private.js` пересоберите браузерный bundle из `protocol-ui`:

```powershell
npm ci
npx esbuild private.js --bundle --platform=browser --target=es2021 --outfile=../assets/private.bundle.js
```

Для рабочей установки серверов и внешних интеграций нужны отдельные конфигурационные значения. Не помещайте реальные секреты, приватные ключи, базы пользователей или `.env` в GitHub; храните их вне репозитория.

## Релизы

Для первой публичной беты используйте тег GitHub Release `beta-v0.1.2`. Готовых установщиков этой версии пока нет: переименование старых файлов не изменит их внутреннюю версию. После сборки v0.1.2 разместите установщики в релизе и создайте для них новые SHA-256-хеши. Папка `релизы/` игнорируется Git, поэтому бинарные файлы не попадут в коммит.

## Лицензия

Для самого Ctrl Messenger отдельная лицензия в этой копии пока не задана. Уведомления о лицензиях сторонних компонентов сохранены рядом с соответствующими файлами. Перед публикацией решите, какую лицензию вы хотите применить к собственному коду; не заменяйте и не удаляйте сторонние уведомления.

## Статус проверки

Исходники включают тесты, но перед выпуском публичной версии их нужно выполнить в среде с установленными Node.js и .NET SDK. TON-контракты и платежные сценарии не следует считать проверенными в основной сети только на основании наличия тестов.
